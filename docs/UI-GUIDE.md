# 跨平台界面规范

手机版 0.1.1 对齐 PC 版 0.4.9 的界面风格。参照 PC 源码提交 `01b76bff9ee7e1f8b7d06459de6e6f4cbf71ffea`，两平台继续在各自目录和仓库内维护样式；手机版不引用 PC 目录中的文件。

本文用于开发者和 Agent 修改源码样式。先选对应入口，保持语义变量、组件状态和系统主题一致，再按末尾的验证流程检查实际界面。PC 版的样式入口以 [PC 仓库](https://github.com/panda472328/yuyin-music) 自己的规范为准。

## 修改入口

| 想修改的内容 | 文件与定位 | 需要同步检查 |
| --- | --- | --- |
| 全局主题配色 | `src/theme.css` 中的 `:root` | 正文、按钮、选中、禁用、错误、歌词与弹层 |
| 字体、字号、间距、圆角、阴影 | `src/styles.css`，从 `:root` 和目标组件类查找 | 长文字、窄屏、键盘焦点与低高度屏幕 |
| 顶栏、品牌与头像菜单 | `.topbar`、`.brand`、`.account-*` | 登录与已登录、头像缺失、菜单打开 |
| 首页卡片与唱片 | `.discovery-card`、`.hero-art`、`.record*` | 320 / 360 像素宽度与横屏，不遮挡文案 |
| 搜索、歌曲列表与选中态 | `.search-*`、`.song-*`、`.is-current` | 空结果、翻页、长标题、收藏及更多操作 |
| 歌词与校准 | `.lyric-window`、`.lyric-lines`、`.source-select`、`.timing-*` | 当前句、校准态、空歌词和歌词来源切换 |
| 播放器与底部导航 | `.player-*`、`.transport`、`.mini-player`、`.bottom-nav` | 进度拖动、底部安全区、歌词滚动、横屏 |
| 操作弹层 | `.sheet-backdrop`、`.sheet*` | 长列表、关闭按钮、危险操作、屏幕键盘 |
| 文案、结构或状态类 | `src/App.tsx` | 保留已有事件、保存确认和无障碍标记 |
| 启动页与 Android 系统栏 | `capacitor.config.ts`、`android/app/src/main/res/values/yuyin_colors.xml`、`values-v26/yuyin_colors.xml`、`values/styles.xml` | API 24–25 和 API 26 以上的图标可读性 |
| 网页与 Android 图标 | `public/icon.svg`、`public/icon.png`、原生 `mipmap-*` 和 `drawable/ic_yuyin.png` | 网页、启动页、桌面图标分别验收 |

使用 `rg` 定位已有类和颜色。全局换色先修改 `theme.css`；当前组件还包含少量硬编码的装饰色、渐变和透明色，需要在 `styles.css` 检索并逐项调整。不能只改变主色就宣称所有界面已换主题。

## 共同的视觉规则

| 用途 | 值 |
| --- | --- |
| 页面底色 `--canvas` | `#f7f8f3` |
| 导航底色 `--sidebar` | `#f1f4ec` |
| 正文 `--ink` | `#4d5a43` |
| 主色 `--green` | `#4c663a` |
| 分隔线 `--line` | `#e6eadf` |
| 字体顺序 | Segoe UI、Microsoft YaHei、system-ui、sans-serif |

其它语义变量同样在 `src/theme.css` 维护：

| 变量 | 当前值 | 用途 |
| --- | --- | --- |
| `--surface` | `#fffefa` | 面板和弹层 |
| `--surface-soft` | `#edf2e6` | 次级背景与控件底色 |
| `--selected` | `#e4edde` | 当前导航与选中项 |
| `--muted` | `#7c8872` | 次级说明 |
| `--subtle` | `#94a188` | 占位与弱提示 |
| `--accent-line` | `#c2d0b7` | 强调边框 |
| `--on-green` | `#f8fbed` | 主色按钮文字与图标 |
| `--danger` | `#ad6556` | 删除和失败文字 |
| `--danger-surface` | `#f8eee4` | 危险状态底色 |
| `--danger-line` | `#ead4c3` | 危险状态边框 |
| `--shadow` | `#37432a1c` | 轻阴影 |
| `--brand-radius` | `14px 14px 14px 4px` | 品牌角形 |

变量名表达用途。新增同一用途的组件直接复用变量；新的视觉用途才添加变量，并同步本文。改变颜色时检查正文与底色、按钮与文字、危险状态的对比，不依赖颜色独自表达选中或错误。

品牌使用绿底米白声波图标、左下角较小的圆角、「余音」和 `YUYIN MUSIC`。首页采用相同的「把日子，听成喜欢的样子」文案、浅绿背景与黑胶唱片。搜索框使用浅灰绿胶囊形状，主要按钮使用绿底米白字，选中导航和歌曲使用淡绿底深绿文字。账号菜单、设置和弹层使用米白面板、细边框及轻阴影。

歌词当前句使用深绿粗体、淡绿高亮底和左侧圆点，普通句使用灰绿文字，来源切换与校准控件采用相同的绿系样式。

## 手机版布局

手机保留底部导航、迷你播放条和底部操作弹层，避免把 PC 侧栏与多列歌曲表挤进窄屏。主要触屏按钮至少 44 像素高，窄屏歌曲列表保留双行文字，首页唱片在右侧独立裁切，不遮挡文案。布局处理手机安全区、320 / 360 像素窄屏和横屏；系统启动页、状态栏沿用米白背景。Android 8 及以上的系统导航栏使用米白背景与深色图标；Android 7 的系统不支持深色导航图标，因此使用品牌绿背景与系统浅色图标，保证可见。

共同配色保存在手机版 `src/theme.css`，页面样式保存在 `src/styles.css`。下次统一调整配色时，分别更新两个仓库并验证各自布局，不建立跨目录依赖。

Android WebView 中没有浏览器地址栏，页面与播放器高度使用 `vh` 单位，兼容项目要求的 WebView 91；不依赖较新浏览器才支持的 `dvh`。预览及错误状态通过明确类名控制，避免依赖 `:has`。

## 组件与状态规则

- 交互保持语义化的 `button`、`input`，保留 `aria-label`、`aria-pressed`、禁用态和 `:focus-visible`。图标和封面不要使文字点击区域失效。
- 手机账号菜单通过点击或触摸打开。悬停仅作支持鼠标设备的补充，现有 hover 规则放在 `@media (hover: hover)` 内。
- 歌曲正在播放用 `.is-current`；底部导航和歌词当前句用 `.active`；歌词来源用 `.selected`。修改组件时同时查看选中、普通、禁用和错误状态，按上下文保留这些类。
- 播放器布局根据 `.player-content`、`.preview-mode`、`.has-alert`、`.timing-visible` 调整。改变高度时同时检查空态、播放、预览提示、错误提示和校准展开，避免控件被底部导航覆盖。
- 歌词当前句保留字体加粗和左侧圆点；修改字体或行高后检查自动滚动及点选句子是否仍准确。样式调整不改变同步偏移或媒体时间。
- 底部弹层内部滚动，关闭按钮保持可点；长歌名可以换行，内容不得通过横向溢出扩大页面。
- 保留 `prefers-reduced-motion`，旋转、平滑滚动和过渡在用户减少动画时降级。

## 推荐修改流程

1. 阅读需求与目标组件，检查当前 Git diff，保留已有工作；按上表找到样式入口。
2. 全局风格改语义变量，局部布局改组件规则；需要新状态时在 React 增加明确类名。不要把保存、登录、歌词或播放业务混入仅样式任务。
3. 同步调整组件中相应的硬编码装饰色。换主色 / 页面底色时核对 Capacitor 背景、原生启动主题和系统栏。
4. 运行 `npm run typecheck`、`npm test`、`npm run build`。保留 `npm run dev` 服务，在另一终端执行 `node scripts/verify-ui.mjs`；脚本使用虚构账号及独立数据，不操作用户会话。
5. 检查登录、首页、搜索、歌单、播放器歌词、账号菜单、设置和弹层截图，覆盖 320 / 360 像素窄屏、844×390 横屏以及长标题。验证可点击、可滚动、无横向溢出；歌词与底部控件同时可用。
6. Android 系统主题或原生布局有改动时构建 APK，在专用设备验证启动页、系统栏和安全区，按 [ANDROID-TESTING.md](ANDROID-TESTING.md) 验证涉及的原生行为。
7. 更新本文中变更的配色与规则，并在贡献说明列出修改、截图、检查结果和未验证范围。跨平台主题变更分别提交到两个仓库。

界面测试通过只证明其测试范围；网页截图不能证明原生系统栏正确，模拟器受控媒体也不能证明真实 Bilibili 长时间播放稳定。
