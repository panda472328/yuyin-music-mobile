# Android 播放回归（2026-10-15）

从手机版 `4d8db74` 开始执行新一轮验证。PC 仓库未修改。本轮发现并修复同 BV 重播读到旧文档的问题，同时增加源站登录弹层的明确提示；正式版本仍为 0.1.3 / versionCode 4，没有发布新版本或推进国内更新清单。

## 发现和处理

1. **同一 BV 重播提前确认成功。** 真实网络下，播放到 103 秒后重新选同一首歌，旧实现可能先返回旧文档的 103 秒位置，再显示新页面归零。现在先停用旧文档并暂停、静音旧媒体，在回调中核对播放代次后才开始新导航；轮询不采用已停用的文档。取消或迟到的旧请求不能发起后续导航。
2. **游客源页面主动暂停并要求登录。** 原始真实测试中，返回桌面约 16 秒继续播放，但随后熄屏期间暂停。单独重试 20 秒熄屏正常，长测则在约一分钟后再现。最终被动记录捕获到 Bilibili 的播放器脚本主动调用 `pause()`，约半秒后出现可见登录弹层。现在当原视频暂停且可见 `.bili-mini-mask` 内包含登录组件时，显示 `BILIBILI_VERIFICATION_REQUIRED`，提示先登录后重新选曲。隐藏的登录组件、单纯存在“登录”文字和普通暂停不触发；不强行自动复播或关闭源站登录层。

## 真实匿名网络

真实网络检查使用先前独立的 index 4 / `emulator-5562`，仅有测试生成的音乐记录，没有真实账号或个人数据。通过安装版的生产 React / Capacitor / 原生播放服务访问 Bilibili；不拦截或伪造网络响应，不执行点赞、评论或登录。

- 游客搜索“晴天”获得 18 条结果；切换歌名 / 视频模式保留输入，搜索后没有自动播放。
- 主动选曲后，真实公开视频 `BV1zy4y127hV` 播放成功，时长 271 秒。
- 用 `adb install -r` 覆盖安装修复后的 Debug APK，原测试队列 18 首、历史 3 首及音量 0.7 保留。该检查仅证明这个测试库的同签名覆盖保留，不代替正式签名升级验收。
- 修复后的真实同曲重播：先定位到 35 秒，再重新播放，约 3.626 秒后返回新文档的 0.531 秒，无旧进度提前完成。
- 返回桌面约 13.618 秒后，音源推进约 14.161 秒且仍在播放；起止采样含轮询误差。
- 随后连续熄屏约 71.928 秒，源站在视频 63.221 秒附近主动暂停并显示登录窗口。播放器正确显示登录验证错误，安装版播放页可见完整提示。**这项记录为源站要求登录，不能计作连续熄屏 71.928 秒播放通过。**

长测仅在开始时安装被动诊断记录器；Home / 熄屏期间未连接源视频的调试目标。记录器保留原 `pause()` 行为，只记录调用和登录层出现时间。主界面与原生桥接通过专用实例的 CDP 检查；浮窗真实原生输入由 instrumentation 另行验证。

本机证据集中在 `.qa/regression-20261015/`，包含原始失败、长测、修复后原生日志、真实网络结果和安装版错误提示截图，不纳入 Git。没有用后来的通过覆盖最初失败记录。
